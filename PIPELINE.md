# CI/CD Pipeline Documentation

## Введение
Данный документ описывает структуру и шаги CI/CD пайплайна для нашего Laravel приложения. Пайплайн настроен с использованием GitHub Actions.

## Ветки и Стратегия (Git Flow)
В репозитории используются следующие долгоживущие ветки:
- `master` / `main` — ветка для продакшена (Production).
- `qa` / `uat` — ветка для предрелизного тестирования (User Acceptance Testing).
- `dev` / `development` — основная ветка для разработки.

Пайплайн запускается автоматически при событиях `push` и `pull_request` в любую из этих трех веток.

## Шаги пайплайна (Jobs)

Пайплайн состоит из двух основных jobs: `test-and-lint` и `deploy-simulation`.

### 1. Test and Lint
Этот блок шагов выполняет проверку качества кода перед развертыванием.

- **Checkout & Setup**: Клонирование репозитория и настройка окружения PHP 8.3 с нужными расширениями и инструментом `pcov` для замера покрытия тестами.
- **Install Dependencies**: Установка зависимостей проекта через Composer (`composer install`).
- **Environment Setup**: Копирование конфигурации `.env.ci` для использования легковесной in-memory SQLite базы данных в ходе тестирования.
- **Execute Tests with Coverage**: Запуск юнит и функциональных тестов Laravel. 
  - *Gate*: Пайплайн завершается с ошибкой, если какой-либо тест не проходит или если покрытие кода (Test Coverage) составляет менее 50%. Для этого используется встроенная функция Laravel: `php artisan test --coverage --min=50`.
- **Static Analysis**: Запуск PHPStan (через Larastan). 
  - *Gate*: Пайплайн завершится с ошибкой при любом найденном нарушении статического анализа.
- **Linting**: Запуск Laravel Pint (PSR-12/Laravel пресет).
  - *Gate*: Инструмент запускается в режиме `--test` (без авто-исправлений). Пайплайн падает при любом нарушении стиля кода.

### 2. Deploy Simulation
Этот блок шагов запускается только если `test-and-lint` завершился успешно и только на событие `push`.

- **Симуляция деплоя**: 
  - Для ветки `dev` копируется файл `.env.dev`.
  - Для ветки `qa` (uat) копируется файл `.env.uat`.
  - Для ветки `master` копируется файл `.env.prod`.
  - После копирования выводится сообщение в формате `Deploying to [ENV] with .env.[env]`.
- **Ручной аппрув**: Для продуктовой ветки `master` используется GitHub Environments (`environment: production`), где в настройках GitHub необходимо назначить обязательного проверяющего (Required Reviewer). Шаг не начнет выполняться до ручного подтверждения.
- **Notification**: Финальный шаг имитирует отправку сообщения maintainer'ам об успешном завершении пайплайна для текущей ветки.

## Как запустить
Пайплайн активируется автоматически после загрузки (push) кода на GitHub. 
Для запуска пайплайна локально можно использовать такие инструменты как `act` (https://github.com/nektos/act), но основное предназначение - это работа на серверах GitHub Actions.
